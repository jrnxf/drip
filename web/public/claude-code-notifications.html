Claude Code notifications on Mac, from the notch.

Add a hook snippet to Claude Code's settings and its hooks show a card from your Mac's notch naming the project and what it needs, whenever it wants permission. Same for Codex and Gemini CLI: the recipes have a snippet for each.

brew install jrnxf/tap/drip

Then add this to ~/.claude/settings.json. If the file has a hooks entry, merge the events and keep your own.

{
  "hooks": {
    "PermissionRequest": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "Notification": [
      {
        "matcher": "elicitation_dialog",
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "PostToolUseFailure": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "ElicitationResult": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ]
  }
}

drip is a free, open-source command-line tool for macOS 13 or newer. It is not Notification Center: it draws its own card, so it needs no Notifications, Accessibility or Automation permission.

How it works

  1. Hooks, not polling. A recipe is a hook snippet you copy into the agent's settings. The one above hooks Claude Code's PermissionRequest (Claude wants to run something) and Notification (a question) events, and the events that show it moved on. The everything recipe adds Stop (the turn is done) and StopFailure (a rate limit, an outage or another API error).
  2. One card per event. Each hook runs drip hook claude, which reads the hook's JSON and shows my-app needs you with what Claude wants, such as Claude wants to run npm install, my-app is done with the last thing Claude wrote, or my-app stopped with the error.
  3. Gone once you answer. Approve in the terminal, or send Claude a prompt, and the card that said it needs you goes.
  4. Or answer on the card. With the approve-from-card recipe, the permission card has Allow and Deny, and a click is Claude's answer. Off by default.
  5. Named by project. The title is the project, from the session's working directory, so several sessions at once stay apart; two folders of the same name read 1/drip and 2/drip.
  6. Replaced in place. Each session's cards share an id, so the waiting card turns into the done card instead of queueing behind it. While you watch the terminal, the done card is quiet and short.
  7. Back to the terminal, or out of the way. A click on the card brings forward the terminal the agent runs in, and its tmux pane. The × on hover, or a right-click, takes the card away and brings nothing forward.

Codex runs a new hook only once you trust it: run /hooks in Codex after you add its hooks.

FAQ

Does drip use macOS Notification Center?

No. drip draws its own card out of the camera notch, or out of the top edge of a screen without one, so it needs no Notifications permission. Cards also show during Do Not Disturb; run drip pause 30m to hold them for a while.

Do I have to change Claude Code's own notification setting?

No. Hooks run alongside it: drip only runs from the hooks you add, and whatever Claude Code did before on a prompt, it still does. If each card comes with a second notification from your terminal, set Local notifications to disabled in its /config.

My settings.json is managed by home-manager or a dotfile manager. What then?

drip never writes your settings. Add the snippet to the source your dotfile manager reads.

What if I am away when Claude Code needs me?

A card that comes up while the screen is locked waits for the unlock, and drip history --missed lists what came up while you were away.

Can I allow or deny from the card?

Yes, with the approve-from-card recipe, which adds --approve to the PermissionRequest hook: Claude Code's and Codex's permission cards get Allow and Deny, and a click is the agent's answer. With nothing clicked in 9 minutes, the terminal asks as usual. Answer in the terminal instead and the card goes. Codex asks in its terminal only once the hook returns, so its card has the buttons only while you are not watching that terminal. Cards from an agent on another machine, and Gemini CLI's, only tell.

How do I get a card out of the way without going to the terminal?

Click the × that takes the icon's place when the pointer is on the card, or right-click, Control-click or Option-click anywhere on it: the card goes back into the notch and nothing comes forward. drip dismiss does the same from the keyboard, and VoiceOver offers Dismiss on every card.

How do I remove the hooks?

Delete the entries whose command is drip hook claude from ~/.claude/settings.json.
