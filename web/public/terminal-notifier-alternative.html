A terminal-notifier alternative for scripts.

drip does the job terminal-notifier does in a script, from the notch instead of Notification Center. Install it with brew install jrnxf/tap/drip and call drip ok build -d finished. Keep terminal-notifier if you want notifications that follow Focus.

brew install jrnxf/tap/drip

The same job in both

Say a thing

# terminal-notifier
terminal-notifier -title build -message finished

# drip
drip ok build -d finished

Say how a command went

# terminal-notifier
if make test; then
  terminal-notifier -title make -message passed
else
  terminal-notifier -title make -message failed
fi

# drip
drip run make test

Ask a question

terminal-notifier's -action and -reply (version 3) print the answer. drip's --yes and --no are an exit status: 0 on yes, 1 on no and 5 when nobody answers.

# drip
drip warn "Deploy to prod?" --yes Deploy --no Cancel && ./deploy.sh

The title stays the title, and terminal-notifier's message becomes drip's detail with -d. The flags are different, so change each call by hand. drip run shows make test finished in green on exit 0, or make test failed (exit 2) in red, with how long it took, and then exits with the command's own status.

drip is a free, open-source macOS CLI that shows scriptable notification cards from the MacBook notch, for builds, deploys and coding agents like Claude Code, Codex and Gemini CLI.

When terminal-notifier is still the right choice

  • You want a Notification Center banner that follows Focus and Do Not Disturb.
  • You want the notification to wait in Notification Center's list afterwards.
  • The Mac runs macOS older than 13, which drip does not support.
  • You need a typed reply from -reply printed to the script.

How it works

  1. drip draws its own card. It grows out of the camera notch, or out of the top edge of a screen without one, so it needs no Notifications permission and does not use Notification Center.
  2. Two words carry over. The title is the bold text and -d is the gray text under it. The first word picks the look: ok, warn, fail or info.
  3. A command can be wrapped. drip run runs it, times it and picks green or red from the exit code. Scripts and && chains work as before.
  4. A question is an exit status. --yes and --no add buttons, and drip exits 0 on yes, 1 on no and 5 when nobody answers.
  5. Nothing is lost while you are away. drip history keeps the cards, and drip history --missed lists what came up while you were away.

FAQ

Is drip a replacement for terminal-notifier?

For alerts about builds, deploys, tests and coding agents, yes. If you want notifications to wait in Notification Center's list and follow Focus, terminal-notifier does that and drip does not.

Is drip a drop-in with the same flags?

No. The flags differ, so change each call by hand. A title and message become a title and -d, as in drip ok build -d finished.

Why is drip not in Notification Center?

So it needs no Notifications permission and can show at the notch, where a glance finds it. The cost is that it does not follow Focus. Cards show during Do Not Disturb, and drip pause holds them for a while instead.

Can I use drip and terminal-notifier together?

Yes. They do not touch each other's settings, so a script can call either.

Does drip work over ssh or on Linux?

No. drip needs a Mac running macOS 13 or newer with someone logged in to the screen. Over ssh there is no GUI session, so drip exits 3.
