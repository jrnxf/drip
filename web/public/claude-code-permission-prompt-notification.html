Get a notification when Claude Code asks for permission.

Add the approve-from-card hooks to ~/.claude/settings.json and a card from your Mac's notch shows what Claude Code wants to run. A short shell command gets Allow and Deny. Install drip first with brew install jrnxf/tap/drip.

brew install jrnxf/tap/drip

Add this to ~/.claude/settings.json ($CLAUDE_CONFIG_DIR/settings.json if you set it). If the file has a hooks entry already, merge the events and keep your own hooks. This is the approve-from-card recipe.

{
  "hooks": {
    "PermissionRequest": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude --approve"
          }
        ]
      }
    ],
    "Notification": [
      {
        "matcher": "elicitation_dialog",
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "PostToolUseFailure": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ],
    "ElicitationResult": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "drip hook claude"
          }
        ]
      }
    ]
  }
}

For a card that only tells you, with no buttons, use the permission-cards recipe: the same snippet with drip hook claude in place of drip hook claude --approve on PermissionRequest. If each card comes with a second notification from Claude Code itself, set Local notifications to disabled in its /config.

drip is a free, open-source macOS CLI that shows scriptable notification cards from the MacBook notch, for builds, deploys and coding agents like Claude Code, Codex and Gemini CLI.

When the card has Allow and Deny

A permission card always shows what the call would do, read from the tool's own input: the command, else the file or the address, else the tool. It never shows only the agent's description of the call. Allow and Deny appear only for a shell command that is short, on one line, in plain ASCII, with no extra options. The card then shows the command character for character.

Every other request is asked in the terminal. The card only tells, and the hook returns at once. That covers:

  • other tools, such as Write, Edit, WebFetch or an MCP tool
  • a command too long for the card
  • a command with a line break, a tab, a run of spaces or a character outside ASCII
  • a command with an option that can change what runs, such as dangerouslyDisableSandbox

How it works

  1. The hook waits on the card. The PermissionRequest hook runs drip hook claude --approve. A click on Allow or Deny is Claude Code's answer, and the tool runs or does not, without the terminal.
  2. You see the command first. The card is titled my-app needs you and shows the command, such as npm install. Allow shows only when the command fits the rules above.
  3. Claude asks in the terminal too. Claude Code asks there at the same time, and the first answer counts. A deny in the terminal takes the card away at once. An allow does, once the tool ends.
  4. Buttons wait for a still card. The buttons take a click only once the card has been still for 0.4 seconds, so a click meant for the card before never answers this one.
  5. No click, no change. Nothing clicked in 9 minutes prints nothing, and the terminal asks as it would without drip. So does a click on the card itself, which brings the terminal forward, and the ×.

FAQ

Can I allow a command from the card without seeing it?

No. The card shows the command, file or tool, never only Claude Code's description of it, and Allow appears only for a short, single-line, plain-ASCII shell command that the card shows character for character.

What happens when the command does not fit on the card?

There is no Allow button. The card only tells you, the hook returns at once and Claude Code asks in the terminal as it would without drip. The same holds for Write, Edit, WebFetch and MCP tools.

Can a stray click allow a command?

It can, which is why the buttons are off by default and you add --approve by choice. The buttons also take a click only once the card has been still for 0.4 seconds.

What if I do nothing about the card?

After 9 minutes the hook prints nothing and the terminal asks as usual. A click on the card itself, or on the ×, does the same.

Does it work when the screen is locked or from another machine?

The card then only tells. A permission card that comes up while the screen is locked or drip pause holds cards has no buttons, and neither has one from another machine, because --approve is local only.
